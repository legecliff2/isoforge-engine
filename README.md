# isoforge-engine
Modular, lightweight 2D isometric RPG engine. C++20, SDL3, Luau, D&D 5e SRD 5.1 rules.
See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

This work includes material from the System Reference Document 5.1 ("SRD 5.1") by Wizards of the Coast LLC, licensed under CC-BY-4.0.

## Content validation
CTest runs `content_validate`, which checks every pack in `content/packs/` and the frozen
corpus in `tests/compat/fl*/` against `schemas/<type>/v<N>.schema.json` (JSON Schema 2020-12,
immutable once released), plus cross-checks (CR/XP, saves/skills, chunk sizes, `content_hash`,
script paths and `contents`), and strict-typechecks every `scripts/**/*.luau` with Engine Core's
`script_check` (`--script-check <exe>`, passed automatically by CMake).

```sh
cmake -S . -B build && cmake --build build
ctest --test-dir build -R content_validate
```
At configure time CMake creates a private venv at `build/content-venv` (`Scripts/` on Windows,
`bin/` elsewhere) and installs the pinned `tools/validate/requirements.txt` into it; system Python
is never modified. That needs network on the first configure. If it fails, the test is disabled
with a warning. Pass `-DENGINE_CONTENT_VALIDATE=OFF` to skip it entirely.

Without CMake: `python3 -m venv .venv && .venv/bin/pip install -r tools/validate/requirements.txt && .venv/bin/python tools/validate/validate_packs.py`.

Chunk files (`chunk@1`) use compact layers: `{"tiles"?, "elevation"?, "flags"?}`, each a 1024-entry row-major
array (index = `y*32 + x`), omitted = all zeros. Flags: bit0 blocks_move, bit1 blocks_sight, bit2 difficult,
bit3 water, bits 4-7 must be 0. Spawns never carry `stable_id` (the loader derives it from coord + spawn index).

`content_hash` is optional. If present, it is the 16-lowercase-hex xxHash3-64 (seed 0) of the **loaded chunk's
canonical little-endian byte layout** (ARCHITECTURE.md §4.5; `compute_content_hash` in
`engine/core/world/src/chunk_codec.cpp`), not of the JSON. The validator reimplements it byte for byte and checks
it against the engine's golden vectors. After editing a chunk, refresh it with `validate_packs.py --rehash`
(updates hashes already present; never touches `tests/compat/`).

## Building

```sh
cmake --preset linux-gcc-debug        # or mac-clang-debug, win-msvc, linux-clang-release, asan, ...
cmake --build --preset linux-gcc-debug
ctest --preset linux-gcc-debug
./build/linux-gcc-debug/game/sandbox/sandbox      # iso grid demo (arrows/WASD pan, Esc quits)
```

SDL3 is fetched and pinned (`release-3.4.8`) by `cmake/Dependencies.cmake`. Configure with
`-DENGINE_HEADLESS=ON` to build only SDL-free modules (null renderer). Linux needs the X11/Wayland
dev packages listed in `.github/workflows/ci.yml`.

Headless demo run (software Vulkan): `Xvfb :99 & DISPLAY=:99 VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json ./sandbox`.

### Shaders (v0)
The SDL_GPU backend ships the `sprite` pipeline as committed SPIR-V (Vulkan) and MSL source (Metal),
generated by `engine/render/sdlgpu/shaders/gen_shaders.py`. D3D12/DXIL is not provided yet, so on
Windows the backend needs a Vulkan driver. Moving to HLSL + SDL_shadercross (ARCHITECTURE.md §6) is a follow-up.

### Vertical slice viewer
`./build/<preset>/game/vertical_slice/vertical_slice [--static] [--seed N] [--steps K] [--zoom Z]` loads
`content/packs/sample.vertical_slice` through `world::FileChunkProvider`, plays Engine Core's headless
`sim::Combat` fight one command per SPACE (A = autoplay), and draws it with `iso2d`. Arrows/WASD pan,
mouse wheel or 1/2 zoom. `--static` shows only the chunk and spawns (no sim).
`--equipment` turns on loadouts; **F3** opens the debug equip / inventory view (selected PC's worn, held and carried
items; UP/DOWN select, TAB next PC, E equip, U unequip, L light / hood / douse; arrows stop panning while it is open).
